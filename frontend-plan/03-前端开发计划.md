# OA 系统 前端分阶段开发计划

> 技术栈：**Vue 3 + TypeScript + Vite + Pinia + Vue Router 4 + Element Plus + Axios**（已确认）
> 开发规范：每阶段完成后 → `npm run build` 通过 + 关键流程自测 → 输出汇报 → **停止等待确认**，再进入下一阶段。
> 接口契约见 `02-接口文档.md`；后端缺口与规避方案见 `01-后端分析报告.md` 第 5 节。

---

## 0. 前置条件与总体说明

- 后端需已启动（`.\mvnw.cmd spring-boot:run`），MySQL + Redis + RabbitMQ 运行中。
- 开发环境建议 Node 18+；用 Vite 脚手架初始化前端工程（可放仓库 `frontend/` 子目录，与后端并列）。
- 前端通过 Vite dev server 代理 `/api` 到 `http://localhost:8080`（避免跨域）。
- **审批人选择**：因后端暂无免权限的用户简表接口（分析报告 §5.3），本计划默认前端**先提供「输入审批人 ID」或「下拉（调用 /api/users，仅 admin 可用）」两种实现**；若你决定后续补后端接口，阶段 F4 再切换到下拉选择。

### 路由与权限总策略
- 静态路由表（`constantRoutes`）＝登录页/注册页/404。
- 动态路由（`asyncRoutes`）＝业务模块（审批/文件/通知，登录即可见）+ 系统管理（按 `permissions` 过滤）。
- 侧边栏菜单由 `usePermissionStore` 根据 `roles`/`permissions` 生成。
- 按钮级权限：自定义指令 `v-permission="['system:user:add']"`，按 `/api/auth/me` 的 `permissions` 控制显隐。

## 阶段 F1：工程搭建与基础框架

**目标**：可运行的前端骨架 + 请求封装 + 路由守卫 + 登录态管理。

| 交付 | 说明 |
|---|---|
| 工程初始化 | Vite + Vue3 + TS + Vue Router + Pinia + Element Plus + Axios + sass 等 |
| 目录结构 | `src/api`、`src/router`、`src/stores`、`src/views`、`src/layout`、`src/utils`、`src/directive`、`src/types` |
| Axios 封装 | 统一 baseURL `/api`；请求拦截注入 `Authorization: Bearer {token}`；响应拦截统一解析 `{code,message,data}`，`code!==200` 抛错，401 清登录态跳登录页 |
| Pinia | `useUserStore`（token/userInfo/登录/登出）、`useAppStore`（侧边栏折叠） |
| 路由守卫 | `beforeEach`：无 token → 登录页；有 token 无 userInfo → 拉 `/api/auth/me`；动态路由注入 |
| 布局组件 | 侧边栏（菜单）、顶栏（面包屑/用户名/登出/通知铃铛占位）、内容区、标签页（可选） |
| 环境配置 | `.env.development` / `.env.production`，dev 代理到 8080 |

**完成标准**：`npm run dev` 可启动，访问 `/login` 正常，未登录跳转拦截生效；`npm run build` 通过。

## 阶段 F2：登录 / 注册 / 退出

**目标**：对接认证接口，打通登录态闭环。

| 交付 | 说明 |
|---|---|
| 登录页 `/login` | 表单（用户名/密码）+ 校验；调 `POST /api/auth/login`；成功存 token + userInfo → 跳首页 |
| 注册页 `/register` | 表单对齐后端校验规则（用户名 3-20、密码 8-20 含字母数字、可选昵称/邮箱/手机）；调 `POST /api/auth/register`；成功提示「等待管理员分配角色」→ 跳登录 |
| 退出登录 | 调 `POST /api/auth/logout` + 清空 Pinia/localStorage → 跳登录页 |
| 首页/工作台 `/dashboard` | 欢迎语 + 用户信息展示（静态占位，无统计数据接口） |

**完成标准**：admin 登录 → 进入首页；错误密码提示正确；注册→登录流程可用；token 过期(401)自动跳登录。

## 阶段 F3：系统管理 — 用户管理 `/system/user`

**目标**：用户列表/搜索/新增/编辑/删除/分配角色。

| 交付 | 说明 |
|---|---|
| 用户列表 | `GET /api/users` 分页 + 用户名/状态筛选；表格列：ID/用户名/昵称/邮箱/手机/状态(switch 或 tag)/创建时间/操作 |
| 新增用户 | 调 `POST /api/auth/register`（公开接口）+ 成功后调 `PUT /api/users/{id}/roles` 分配角色（需要 `GET /api/users/{id}/roles` 回显、`GET /api/roles/all` 下拉） |
| 编辑用户 | 弹窗表单 → `PUT /api/users/{id}` |
| 删除用户 | `DELETE /api/users/{id}` + 二次确认 |
| 分配角色 | 弹窗多选（`GET /api/roles/all`）→ `PUT /api/users/{id}/roles`；回显 `GET /api/users/{id}/roles` |
| 权限控制 | 页面需 `system:user:list`；新增/编辑/删除/分配按钮用 `v-permission` |

**完成标准**：admin 可完成用户全流程；无权限账号（如普通注册用户）访问该路由被拒/菜单隐藏。

---

## 阶段 F4：系统管理 — 角色管理 `/system/role`

**目标**：角色 CRUD + 分配菜单。

| 交付 | 说明 |
|---|---|
| 角色列表 | `GET /api/roles` 分页 + 名称/状态筛选 |
| 新增/编辑角色 | 弹窗表单（name/code/description/status）→ `POST`/`PUT /api/roles[/{id}]`；code 唯一校验提示 |
| 删除角色 | `DELETE /api/roles/{id}` + 二次确认 |
| 分配菜单 | 弹窗内嵌菜单树（`GET /api/menus/tree`，树勾选，目录/菜单/按钮全可选）→ `PUT /api/roles/{id}/menus`；回显 `GET /api/roles/{id}/menus` |
| 权限控制 | `system:role:list` / `add` / `edit` / `remove` / `assign` |

**完成标准**：角色全流程可用；分配菜单后，挂该角色的用户权限实时生效（后端已做缓存失效）。

## 阶段 F5：系统管理 — 菜单管理 `/system/menu`

**目标**：菜单树 CRUD。

| 交付 | 说明 |
|---|---|
| 菜单树表格 | `GET /api/menus/tree` 树形展示；类型列映射 目录/菜单/按钮 |
| 新增/编辑菜单 | 弹窗表单（parentId 树选择/type 联动：按钮必填 perms）+ 校验 |
| 删除菜单 | `DELETE /api/menus/{id}`（有子菜单后端拒删，提示） |
| 权限控制 | `system:menu:list` / `add` / `edit` / `remove` |

**完成标准**：菜单 CRUD 可用；新增按钮权限后，`/api/auth/me` 的 permissions 变化可在重新登录后看到。

## 阶段 F6：审批模块 — 请假 `/approval/leave`

**目标**：请假提交/我的列表/待审列表/详情/审批/撤回/审批记录时间线。

| 交付 | 说明 |
|---|---|
| 提交请假 `/approval/leave/create` | 表单：类型(年/事/病假)、起止日期(日期选择器)、天数(自动或手动)、事由、审批人；调 `POST /api/approvals/leave` |
| 我的请假 `/approval/leave/my` | 分页 + 状态筛选（草稿/待审/通过/拒绝/撤回）；行内操作：待审可撤回、查看详情 |
| 待我审批 `/approval/leave/pending` | 分页；行内操作：通过/拒绝（弹窗填意见）/详情 |
| 详情（共用弹窗或抽屉） | 展示 LeaveVO + 审批记录时间线（`GET /api/approvals/records?businessType=1&businessId={id}`） |
| 动作调用 | 通过/拒绝 `PUT /{id}/approve|reject`（body `{comment}`）；撤回 `PUT /{id}/cancel` |
| 权限控制 | 登录即可；操作按钮按当前用户身份（申请人可撤回/审批人可通过）显示 |

**完成标准**：admin 提交请假给另一账号 → 该账号登录在「待我审批」看到 → 通过 → 申请人「我的请假」状态变已通过 + 收到系统通知。

## 阶段 F7：审批模块 — 报销 `/approval/reimburse`

**目标**：同请假，业务字段为金额/类别。

| 交付 | 说明 |
|---|---|
| 提交报销 `/approval/reimburse/create` | 表单：金额(>0 两位小数)/类别/事由/审批人；调 `POST /api/approvals/reimburse` |
| 我的报销 / 待我审批 | 同请假列表结构 |
| 详情 + 审批记录 | businessType=2 |
| 动作调用 | 同请假 |

**完成标准**：报销全流程闭环；状态机非法流转提示正确（如已通过再审批 → 400 提示）。

## 阶段 F8：通知中心 `/message`

**目标**：通知列表 + 未读角标。

| 交付 | 说明 |
|---|---|
| 顶栏铃铛 | 轮询 `GET /api/messages/unread-count`（建议 60s）显示角标 |
| 通知列表 `/message` | `GET /api/messages` 分页 + 已读/未读筛选；行点击 `PUT /api/messages/{id}/read` |
| 全部已读 | `PUT /api/messages/read-all` |
| 通知下拉（可选） | 顶栏弹出最近 10 条未读 + 「全部已读」 |

**完成标准**：审批通过后申请人未读数 +1；标记已读后角标更新。

---

## 阶段 F9：文件管理 `/file`

**目标**：文件上传/列表/下载/删除。

| 交付 | 说明 |
|---|---|
| 文件列表 `/file` | `GET /api/files` 分页 + 名称筛选；展示文件名/大小(格式化)/类型/上传人/时间 |
| 上传 | Element Plus `el-upload`（`POST /api/files/upload`，字段 `file`），限制 ≤10MB + 白名单后缀；上传成功刷新列表 |
| 下载 | axios `responseType:'blob'` + `Authorization` 头，按 `FileVO.url`（`/api/files/{id}/download`）取流 → Blob URL 触发下载（文件名用后端 `originalName`） |
| 删除 | `DELETE /api/files/{id}`，仅上传者或 admin 显示删除按钮（当前用户 `userInfo.user.id === uploaderId` 或 `roles` 含 `admin`） |
| 权限控制 | 登录即可（全部文件共享可见） |

**完成标准**：上传/下载/删除全流程可用；非法类型上传被拒提示。

## 各阶段依赖关系

```
F1 搭建 ──▶ F2 认证 ──┬─▶ F3 用户 ─▶ F4 角色 ─▶ F5 菜单
                      ├─▶ F6 请假 ─▶ F7 报销 ─▶ F8 通知
                      └─▶ F9 文件 ─▶ F10 收尾
```
- F2 之后，F3-F9 相互独立，可并行开发（建议按 F3→F4→F5→F6→F7→F8→F9 顺序）。
- 每个阶段交付一个可编译通过的里程碑，独立汇报确认。
