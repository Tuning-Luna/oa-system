# OA 系统 前端开发提示词（可直接投喂 Claude Code 执行）

> 使用方法：每个阶段开头都需附带 **「公共前置段」** + 对应 **「阶段提示词」**，一次性投喂给一个新的 Claude Code 会话（工作目录 = 前端工程目录）。
> 完成后按每阶段「完成标准」自检 → `npm run build` 通过 → 汇报 → **停止等待确认**。
> 接口契约：`02-接口文档.md`；后端约束：`01-后端分析报告.md`。

## 公共前置段（每个阶段都要带上）

```text
你现在是一名资深前端工程师，负责开发「企业协同办公管理系统（OA）」的前端。
本项目后端是已完成的 Spring Boot 4 单体服务（Java 后端，端口 8080），接口契约见仓库根目录 `frontend-plan/02-接口文档.md`（请先阅读该文件，理解统一返回结构、鉴权方式、枚举字典，再动手编码）。

技术栈（已确认，禁止更换）：
- Vue 3（<script setup lang="ts">）+ TypeScript + Vite
- Pinia（状态管理）+ Vue Router 4
- Element Plus（UI 组件库，全量或按需引入均可，建议全量便于开发）
- Axios（网络请求）
- 样式：Sass/SCSS

硬性规范：
1. 不做一次性完整项目，只完成本阶段列出的功能；不要实现后续阶段的内容。
2. 每个阶段完成标准包含 `npm run build` 通过、关键流程自测通过。
3. 代码符合企业规范：TS 类型齐全（所有接口响应定义 interface，放在 src/api/types.ts 或各模块文件内）、组件化、避免过度设计、不写无意义代码。
4. 接口调用必须统一走 src/utils/request.ts 封装（自动带 token、统一解析 code/message、401 跳登录）。
5. 涉及 Element Plus 组件用法不确定时，先查阅官方文档确认再编码。
6. 完成后输出：完成了什么 / 新建修改了哪些文件 / 如何运行自测 / API 对接了哪些接口 / 下一步计划。停止等待确认。
7. 如发现后端接口与本提示词描述不一致（缺字段、返回结构不同），先停止并说明，不自行猜测。

关键后端约束速查：
- 登录返回：{ token, tokenType:"Bearer", expiresIn, user }；所有请求头带 Authorization: Bearer <token>。
- 统一响应 { code, message, data }；code===200 成功；401 未认证（前端清登录态跳登录）。
- 分页参数统一传 pageNum/pageSize（默认 1/10，上限 100）；分页响应 { total, records, pageNum, pageSize }。
- 时间格式 yyyy-MM-dd HH:mm:ss，日期 yyyy-MM-dd。
```

## 阶段 F1 提示词：工程搭建与基础框架

```text
【本阶段目标】搭建前端工程骨架 + Axios 封装 + Pinia + 路由守卫 + 布局组件。不实现任何业务页面（登录页可只放占位，本阶段不做登录逻辑）。

【任务】
1. 用 Vite 创建 Vue3 + TypeScript 工程（目录名 frontend），安装 vue-router、pinia、element-plus、axios、sass。
2. 配置 .env.development（VITE_API_BASE_URL=/api）与 vite.config.ts 代理 /api → http://localhost:8080（本地联调）。
3. 目录结构：src/api、src/router、src/stores、src/views、src/layout、src/utils、src/directive、src/types。
4. src/types/index.ts 定义全局类型：Result<T>、PageResult<T>、UserVO、UserInfoVO、LoginResponse（字段见接口文档）。
5. src/utils/request.ts：Axios 实例，baseURL 取 env；请求拦截器注入 Authorization: Bearer <token>（token 从 localStorage 读，key: oa_token）；响应拦截器：HTTP 200 且 code===200 返回 data；code!==200 用 ElMessage 提示 message 并 reject；HTTP 401 清空 token 并跳 /login；其他状态按 message 提示。
6. src/stores/user.ts：state={ token, userInfo }；actions：login(调用 /api/auth/login 并落 localStorage)、logout(调 /api/auth/logout + 清空)、fetchMe(调 /api/auth/me 存 userInfo)。
7. src/router：constantRoutes = [ /login, /register, /404 ]；路由守卫 beforeEach：无 token 且目标非白名单 → 跳 /login；有 token 无 userInfo → await fetchMe；本阶段动态路由暂不注入（F2 再做），守卫只做登录拦截。
8. src/layout：侧边栏(菜单占位) + 顶栏(面包屑、用户名、登出按钮占位) + <router-view>。用 Element Plus el-container。
9. 全量引入 Element Plus（main.ts import 'element-plus/dist/index.css'）并挂载 zh-cn 语言包。

【完成标准】npm run dev 启动无报错；未登录访问任意非白名单路由被重定向到 /login；npm run build 通过。
```

## 阶段 F2 提示词：登录 / 注册 / 退出 / 首页

```text
【本阶段目标】对接认证接口，打通登录态闭环 + 动态路由注入 + 侧边栏菜单生成。

【任务】
1. 登录页 /login：Element Plus 表单（用户名、密码、校验必填），提交调 store.user.login；成功后调 fetchMe，再跳首页；错误用 ElMessage 提示后端 message。
2. 注册页 /register：字段 用户名(3-20 字母数字下划线)、密码(8-20 且含字母和数字)、昵称、邮箱(可选)、手机(可选)；前端做同规则校验（与后端一致）；提交调 POST /api/auth/register；成功后 ElMessage 提示「注册成功，等待管理员分配角色后登录」并跳 /login。
3. 退出登录：顶栏按钮 → store.user.logout() → 清空 token/userInfo → 跳 /login。
4. 动态路由 + 菜单（核心）：
   - 定义业务路由表 asyncRoutes（登录可见）：dashboard、approval/leave/my、approval/leave/create、approval/leave/pending、approval/reimburse/*、message、file。
   - 定义系统管理路由表 sysRoutes，每个路由 meta.roles 或 meta.permissions 标注所需权限标识（如 system:user:list）。
   - usePermissionStore：根据 userInfo.permissions 过滤 sysRoutes 生成可注入路由；把 业务路由 + 过滤后的系统路由 addRoute 到 router；并生成侧边栏菜单树（目录/菜单两级，图标用 Element Plus icons）。
   - fetchMe 完成后才注入路由，注入后 next({...to, replace:true}) 防刷新 404。
5. 首页 /dashboard：欢迎卡片（昵称、角色 tag）、说明文案（数据统计接口未提供，本页为静态占位）。
6. 布局完善：侧边栏折叠、顶栏面包屑、用户名下拉(个人中心占位/退出)。
7. 路由重定向：/ → /dashboard；无权限访问系统管理路由 → 404 页。

【完成标准】admin 登录：进入首页、侧边栏出现「系统管理→用户/角色/菜单」+ 业务菜单；普通注册用户(无角色)登录：系统管理菜单不出现，访问其路由被拒到 404；退出后再访问受保护路由被重定向登录页；刷新页面路由不丢失；npm run build 通过。
```
